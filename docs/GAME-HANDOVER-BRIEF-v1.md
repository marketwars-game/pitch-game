- **ไฟล์ที่คาดว่าต้องแก้ (ยืนยันกับ CODE-FILE-MAP อีกครั้ง):**

| 2 | หักออมก่อนใช้ / เงินสำรอง 6 เดือน | รายจ่าย = รายได้ − เงินออม; สำรองฉุกเฉิน 6 เท่าของรายจ่าย |

## 5. AI Judges 3 ตัว (แก้ `judge-prompts.ts`)

**หลักการร่วมทุกตัว:** ให้รางวัลความเฉพาะเจาะจงต่อเคสพี่เก่ง / ลงโทษความ generic — **ห้าม**สั่งให้ judge "ตรวจจับว่า AI เขียนไหม" (ไม่แม่น เสี่ยงกล่าวหาผิด) ใช้เกณฑ์ความตรงเคสแทน ให้ผลเดียวกันโดยไม่มีดราม่า

| Judge | บทบาท | เกณฑ์หลัก |
|---|---|---|
| **The Professor** | อาจารย์การเงิน | ใช้เครื่องมือถูกชิ้น ถูกจังหวะ ถูกต้องตามนิยามไหม (ฝังนิยาม 7 ชิ้นจากข้อ 4 ใน system prompt) · ≥1 ชิ้น = ผ่านเกณฑ์, 2–3 ชิ้นที่ใช้อย่างถูกต้อง = โบนัส · เครื่องมือที่หยิบมาแปะชื่อโดยใช้ผิดบริบท = ไม่นับ |
| **The Skeptic** | **รับบทพี่เก่งเอง** | ตอบความกลัวจริงไหม โดยเฉพาะประโยค "ลงทุนคือพนัน" กับแผลปี 65 · ข้อความ generic โดนตอบแบบ "พูดเหมือนเซลล์ประกันเลยน้อง 😒 พี่บอกว่าพี่เคยเจ็บมา" · **output พิเศษ:** นอกจากคะแนน+comment ให้เขียน **ข้อความตอบกลับสั้นๆ ในบทพี่เก่ง** (แสดงในมือถือผู้เล่นเหมือนแชทเด้ง — องก์ 1 ของเฉลย) |
| **The Communicator** | เพื่อนที่อ่านแชท | เหมือนข้อความที่มนุษย์พิมพ์หาพี่ที่สนิทไหม ภาษาคน ไม่ใช่ศัพท์การเงิน/โบรชัวร์ · ความสั้นกระชับ+น้ำเสียงจริงใจได้คะแนน |

**เจตนาให้ 3 มุมขัดกันได้:** ข้อความวิชาการแน่นอาจโดน Communicator ติ / ข้อความฮาอาจโดน Professor หัก — ความขัดแย้งนี้คือ drama ตอนเฉลย อย่า normalize คะแนนให้เท่ากัน

**นโยบายใช้ AI ช่วยเขียน:** อนุญาต และ MC ประกาศบนเวที ("ใช้ AI ได้ แต่กรรมการให้คะแนนคนที่รักษาพี่เก่งถูกจุด") — rubric ข้างบนทำให้คำตอบ ChatGPT ดิบๆ ที่ไม่มีเครื่องมือ/ไม่ตอบแผลปี 65 แพ้เอง

## 6. Reveal 4 องก์ (10 นาที — ส่วนใหญ่คือ MC + จอ ไม่ใช่โค้ดใหม่)

1. **"พี่เก่งตอบกลับแล้ว" (2')** — ผู้เล่นเห็นข้อความตอบกลับจาก Skeptic ในมือถือตัวเอง · MC: "ใครโดนพี่เก่งดุบ้าง ยกมือ"
2. **เปิดคะแนน 3 กรรมการทีละคน (3')** — Top 3 ต่อกรรมการ โชว์ความขัดแย้งของมุมมอง
3. **Podium + อ่านแชมป์ (3')** — MC อ่านข้อความอันดับ 1 ออกเสียง + breakdown "ฟัง → หลักการ → ก้าวเล็ก"
4. **พลิกกล้อง (2')** — "แล้วใครจะพิมพ์ข้อความนี้หาพี่เก่งในใจคุณ — หรือกล้าพิมพ์หาตัวเอง" → ส่งเข้าช่วง Dime CTA

**เช็คกับ engine:** ข้อ 1 ต้องการให้ผู้เล่นเห็นผลรายบุคคลบนมือถือหลัง judging — Solo Mode มี result view รายคนอยู่แล้ว ยืนยันว่า field ตอบกลับของ Skeptic แสดงได้ ถ้าต้องเพิ่ม field ใน JudgeResponse ให้ถือเป็น content-schema change เล็ก (ยอมรับได้) ไม่ใช่ engine change

## 7. งานที่ chat เกมต้องส่งมอบ (ตาม phase-gate)

1. **Mockup/UI flow** — หน้า Challenge (การ์ดพี่เก่ง), หน้า Writing (การ์ดย่อ + กล่องเครื่องมือ + hint), หน้า Result (ข้อความพี่เก่งตอบกลับ) → รอคอนเฟิร์ม
2. **Architecture/แผนไฟล์** — รายการไฟล์แก้จริงหลังเช็ค CODE-FILE-MAP + raw fetch → รอคอนเฟิร์ม
3. **Open questions เคลียร์** → รอ **"เริ่มได้"**
4. Implement → deploy → **test plan:** (ก) คน 5–10 คนเล่นจริงบนมือถือ (ข) ทดสอบคำตอบ 4 แบบ: มือใหม่สั้นๆ / คนเก่งหลายเครื่องมือ / **copy จาก ChatGPT ดิบๆ (ต้องแพ้)** / ข้อความฮาไร้สาระ (Communicator สูง Professor ต่ำ — ต้องไม่ชนะรวม) (ค) จับเวลา end-to-end ให้อยู่ใน 30 นาที

## 8. Out of scope (ห้ามทำ)

- ห้ามแตะ engine / flow states / realtime mechanism
- ไม่มี multi-persona สุ่ม (ตัดสินใจแล้ว: persona เดียว)
- ไม่มี live twist กลางเกม (ตัดสินใจแล้ว: ไม่ใช้)
- ไม่มี AI-detection ใน judges
- ไม่เปลี่ยน model จาก claude-haiku-4-5
